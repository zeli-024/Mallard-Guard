# 1.54c-beta-7

Continuous Guard now follows the intended input: hold guard to keep blocking, then press attack to immediately restart the parry window. The previous recharge does not prevent this attempt, and a new press can restart an already-open window. Holding attack does not repeatedly restart it. Actual attacks and mining remain suppressed.

The attempt reuses the held item and guard hand. Accumulated blocks remain intact. Changed items, item cooldowns, consumable priority, disabled parrying, and pending or completed guard breaks still prevent an invalid attempt. Every accepted restart confirms its fresh window to the client, including when its numeric status happens to match the previous update.

Animation starts locally on the press while combat remains server-authoritative. Without an eligible Punchy pose, the guarding hand plays the vanilla cosmetic swing, including for shields, then returns to blocking. The fixed first-person/third-person guard pose does not cover that swing. The temporary swing state is bounded by the parry window and cleared on guard end or disconnect.

With Punchy, the new press interrupts the old pose, reaction, or return and randomly chooses from the existing eligible preset pool. The configured entry duration and easing remain in use; entry still defaults to 150 ms. Server confirmation does not start it twice. A successful continuous parry recovers to the held guard pose after its reaction/hitlag instead of marking that pose spent and lowering it. Ordinary guarding retains its existing successful-parry return behavior. Placement previews remain separate.

Continuous Guard and Parry Healing remain disabled by default. Existing particle defaults, center-impact artwork, UI theme, item rules and healing amounts are preserved. Continuous Guard's config comment and tooltip now explain the recharge bypass. Config revision 75 and packet protocol 55 are unchanged; install this correction on both clients and server.

Validation: 39 corrected current-source state/healing checks; 12 settings/save codec roundtrips and UI constructor checks; client attack-edge/cancellation/mining checks; current-source Punchy restart, randomized-selection and reaction-routing fixtures; current-source hand-renderer fixtures covering normal guarding, weapon/shield cosmetic swings and Punchy ownership; existing configuration/UI and center-impact regression checks; all 82 Java files syntax parsed.

These are focused checks with controlled dependency stubs. A complete Java 21/NeoForge Gradle build and in-game multiplayer/animation verification are still required; this environment has Java 17 and cannot download the Gradle wrapper.
