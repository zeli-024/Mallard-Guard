# 1.54c-beta-8

Fixes Continuous Guard's second recharge reset. A parry input starts one timer; returning to held blocking keeps that timer running instead of loading it again. This applies to weapons and shields. Ordinary guarding outside Continuous Guard retains its previous blocking/recharge behavior. Perfect and regular successful-parry reductions are unchanged.

The primary button while guarding now sends a dedicated parry request, not an attack-start message. Each request receives a matching authoritative reply, including rejected or numerically unchanged attempts. The client ignores earlier ordinary status updates while waiting and ignores replies belonging to an older press. This prevents meter rewinds and duplicate confirmation effects. The reply replaces the usual status message for that request; it does not add a second status send. No request queues or retained per-attempt collections are introduced.

Vanilla cosmetic swings are used only when Punchy is absent. If Punchy is installed, a parry input cycles the existing eligible presets without starting an attack swing, including when compatibility is disabled or no preset can play. A restart that cannot take ownership leaves the existing presentation alone. Entry timing still defaults to 150 ms; newer poses interrupt the old pose or reaction immediately and use the existing entry blend.

Parry recharge is the only timer bypassed. Shared client/server item eligibility still honors Respect Item Cooldown when enabled and attack readiness independently. No item cooldown or attack cooldown is cleared. Native shield-disable cooldowns, changed held items, consumable priority, accumulated blocks, pending guard breaks and the release requirement still prevent invalid attempts. Rejected replies restore the authoritative state and clear the temporary cosmetic prediction.

Existing particle defaults, artwork, UI settings, healing behavior and optional-feature defaults are unchanged. Configuration revision remains 75. Network protocol is now 56 because of the dedicated parry request/reply messages: update both clients and server.

Validation: 56 current-source state/healing/recharge/cooldown checks; current shared eligibility checks on client/server; current client status/reply checks for stale updates, rapid presses, duplicate replies and rejected/broken guards; current server sync checks for one reply per request, unchanged-state acknowledgement, status suppression and pose broadcasts; settings/save and new request/reply codec roundtrips; client input/fallback/mining checks; Punchy selection/restart/reaction checks; hand-renderer checks; existing config/UI and center-impact checks; all 82 Java files syntax parsed.

These checks use controlled dependency stubs. Full Java 21/NeoForge compilation and in-game multiplayer/animation verification remain unverified here; only Java 17 is installed and the Gradle wrapper download is unavailable.
