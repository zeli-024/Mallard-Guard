# 1.54c-beta-4

- Active item rules retain their own compiled lists. Large lists no longer fight editor previews for cache space; tags and exceptions retain their existing behavior.
- Item assignment drafts reuse their encoded/compiled rules instead of joining entire lists each frame. Assigned-list scrolling reuses row controls and keeps the search/rule fields intact.
- Server Apply validates sections independently, saves the shared config once, and sends updates after a successful commit. Failure handling restores previous live values and preserved server/enforcement files.
- Client Apply restores previous values and touched config/pose files if saving fails. Enforced personal settings are restored correctly on exceptional paths.
- Login, settings requests and config broadcasts use bounded snapshot chunks, with complete-only application and timeout/disconnect cleanup. Network protocol is now 53; update both server and clients.
- Migration originals are preserved on disk rather than retaining all saved-world config bytes in heap. Accepted large assignment files are no longer skipped by the former 1 MiB snapshot cutoff.
- Spark Tracer birth/color/bounds data is stored once per tick group. Dot positions, count, tick behavior, colors, fading, bounce paths and render order remain the same.

Defaults remain Flying Sparks 8%, Spark Debris 4%, Spark Tracers 12%; Perfect 50% and Damage 25% for all three. Punchy entry defaults remain 150 ms, with the agreed slider/wheel increments and 500 ms maximum. No GPU effect or visual-quality reductions were made.

Existing low-end testing found acceptable performance under the tested configurations. GPU performance is not treated as a demonstrated fault in this release.

Validation: current-source assignment, slider, compatibility, particle, storage and chunk fixtures; exact old/new tracer comparison across 30,720 configurations; save-failure rollback tests; 1.5 MiB snapshot roundtrip; all 80 Java sources syntax-parsed. These use controlled dependency stubs where necessary. Full Java 21/NeoForge Gradle compilation and in-game multiplayer validation are not available in this workspace.

Recommendations that alter behavior (rule precedence, dot budgets, distance-based physics, observation-save durability) were not applied. Field-level config patches and further compatibility/GPU redesigns remain separate follow-up work; this release addresses the confirmed problems and safe structural improvements.
